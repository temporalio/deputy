# Verifying Deputy Releases

Deputy releases are signed using [Sigstore](https://sigstore.dev) keyless signing. This provides cryptographic proof that release artifacts were built by Deputy's official GitHub Actions workflow, not by a compromised system or malicious actor.

## What's signed?

Each release includes:

| File | Description |
|------|-------------|
| `checksums.txt` | SHA256 checksums for all release artifacts |
| `checksums.txt.bundle.json` | Sigstore bundle (signature + certificate) |

The signature covers `checksums.txt`, which in turn covers all binaries and archives. Verify the signature once, then verify individual files against the checksums.

## Quick verification

```bash
# Download the release files you need, plus verification files
TAG=v1.0.0  # Replace with actual version tag
VERSION=${TAG#v}  # Strip 'v' prefix for archive names
curl -fsSLO "https://github.com/picatz/deputy/releases/download/${TAG}/deputy_${VERSION}_linux_amd64.tar.gz"
curl -fsSLO "https://github.com/picatz/deputy/releases/download/${TAG}/checksums.txt"
curl -fsSLO "https://github.com/picatz/deputy/releases/download/${TAG}/checksums.txt.bundle.json"

# Verify the signature
cosign verify-blob \
    --bundle checksums.txt.bundle.json \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com \
    --certificate-identity-regexp 'https://github.com/picatz/deputy/.github/workflows/release.yml@.*' \
    checksums.txt

# Verify the checksum
sha256sum -c checksums.txt --ignore-missing
```

## What the verification proves

The `cosign verify-blob` command verifies:

1. **Signature validity**: The signature matches the checksums file
2. **Certificate chain**: The certificate was issued by Sigstore's Fulcio CA
3. **OIDC issuer**: The signing identity came from GitHub Actions (`token.actions.githubusercontent.com`)
4. **Workflow identity**: The certificate subject matches Deputy's release workflow

The certificate embeds claims from the GitHub Actions OIDC token:

```
Issuer: https://token.actions.githubusercontent.com
Subject: https://github.com/picatz/deputy/.github/workflows/release.yml@refs/tags/vX.Y.Z
```

This proves the artifact was signed during a run of Deputy's official release workflow, triggered by a version tag.

## Verification script

For automated environments, here's a complete verification script:

```bash
#!/bin/bash
set -euo pipefail

TAG="${1:?Usage: $0 <tag> [os] [arch]}"  # e.g., v1.0.0
OS="${2:-linux}"
ARCH="${3:-amd64}"

VERSION="${TAG#v}"  # Strip 'v' prefix for archive names
BASE_URL="https://github.com/picatz/deputy/releases/download/${TAG}"
ARCHIVE="deputy_${VERSION}_${OS}_${ARCH}.tar.gz"

# Download
echo "Downloading Deputy ${TAG} for ${OS}/${ARCH}..."
curl -fsSLO "${BASE_URL}/${ARCHIVE}"
curl -fsSLO "${BASE_URL}/checksums.txt"
curl -fsSLO "${BASE_URL}/checksums.txt.bundle.json"

# Verify signature
echo "Verifying signature..."
cosign verify-blob \
    --bundle checksums.txt.bundle.json \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com \
    --certificate-identity-regexp 'https://github.com/picatz/deputy/.github/workflows/release.yml@.*' \
    checksums.txt

# Verify checksum
echo "Verifying checksum..."
sha256sum -c checksums.txt --ignore-missing

# Extract
echo "Extracting..."
tar -xzf "${ARCHIVE}"

echo "Done! Deputy ${TAG} installed and verified."
./deputy --version
```

## Inspecting the bundle

The Sigstore bundle (`.bundle.json`) contains both the signature and the certificate. To inspect:

```bash
# View bundle contents
jq . checksums.txt.bundle.json

# Extract and decode the certificate
jq -r '.verificationMaterial.certificate.rawBytes' checksums.txt.bundle.json | base64 -d | openssl x509 -noout -text
```

Key fields to check:

- **Issuer**: Should be `sigstore.dev` (Fulcio)
- **Subject Alternative Name**: Contains the GitHub Actions workflow URI
- **OIDC Issuer extension**: `https://token.actions.githubusercontent.com`

## Transparency log

Sigstore records all signatures in a public transparency log (Rekor). The bundle format includes the Rekor log entry, so verification automatically checks the transparency log.

Search for entries at [rekor.sigstore.dev](https://search.sigstore.dev/).

## Verifying SBOMs

Each release includes SBOMs generated by Deputy itself (dogfooding), with their own Sigstore bundles:

| File | Description |
|------|-------------|
| `deputy_vX.Y.Z.sbom.cdx.json` | CycloneDX SBOM |
| `deputy_vX.Y.Z.sbom.cdx.json.bundle.json` | CycloneDX Sigstore bundle |
| `deputy_vX.Y.Z.sbom.spdx.json` | SPDX SBOM |
| `deputy_vX.Y.Z.sbom.spdx.json.bundle.json` | SPDX Sigstore bundle |

To verify an SBOM:

```bash
TAG=v1.0.0
cosign verify-blob \
    --bundle "deputy_${TAG}.sbom.cdx.json.bundle.json" \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com \
    --certificate-identity-regexp 'https://github.com/picatz/deputy/.github/workflows/release.yml@.*' \
    "deputy_${TAG}.sbom.cdx.json"
```

## Why keyless signing?

Traditional code signing requires managing private keys, which creates security risks (key compromise, rotation complexity). Sigstore's keyless approach:

1. Uses short-lived certificates (10 minutes)
2. Binds identity to OIDC tokens (GitHub Actions in our case)
3. Records all signatures in a public transparency log
4. No secrets to manage or rotate

The tradeoff is verification requires network access to Sigstore's infrastructure (Fulcio CA, Rekor log).

## Offline verification

For air-gapped environments, you can:

1. Pre-fetch the Sigstore root certificates
2. Use `--offline` flag with cached trust material
3. Or verify checksums only (weaker, but no network required)

See [Cosign offline verification](https://docs.sigstore.dev/cosign/verifying/offline/) for details.
